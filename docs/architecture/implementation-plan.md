## 二、核心模块设计

### 2.1 数据提取模块 (extractor.js)

**功能**：从公告正文中智能提取结构化字段

**提取字段**：
```javascript
{
  recruitCount: number | null,      // 招考人数 (正则: "招聘XX人")
  examDate: string | null,          // 笔试日期 (YYYY-MM-DD)
  examTime: string | null,          // 笔试时间 (HH:MM-HH:MM)
  examSubjects: string[],           // 考试科目 ["行测", "申论"]
  examType: string | null,          // 考试类型 (事业单位/公务员/教师等)
  registrationDeadline: string,     // 报名截止时间
  examLocation: string | null,      // 考试地点
  salaryRange: string | null        // 薪资范围 (如果有)
}
```

**实现策略**：
1. 正则表达式匹配常见模式
2. 关键词字典匹配
3. 日期解析器（支持多种格式）

### 2.4 定时任务设计

**调度方案**：Cloudflare Workers Cron Triggers

**任务配置**：
```javascript
// wrangler.toml
[triggers]
crons = [
  "7 2 * * *",    // 每天凌晨 2:07 (避开整点)
  "23 14 * * *"   // 每天下午 14:23
]
```

**执行流程**：
1. 遍历所有 enabled 网站
2. 逐个爬取（带延迟）
3. 数据提取 + 分类
4. 去重 + 存储
5. 记录日志
6. 发送统计报告（可选）

**合规要求**：
- 每个网站间隔 1-2 秒
- 单次任务总时长 < 30 分钟
- 失败重试 3 次
- 记录所有操作日志

## 四、合规性保障

### 4.1 爬虫合规
- ✅ **公开信息**：仅爬取政府公开发布的招考公告
- ✅ **明确标识**：User-Agent 标识为 "KaoQingBot/1.0"
- ✅ **访问频率**：每天 1-2 次，间隔 12 小时
- ✅ **请求延迟**：每个网站间隔 1-2 秒
- ✅ **遵守 robots.txt**：检查并遵守网站爬虫规则
- ✅ **错误重试**：失败后指数退避，最多 3 次
- ✅ **数据来源标注**：每条公告标注原始来源 URL

### 4.2 数据使用合规
- 仅用于信息聚合展示，不做商业用途
- 保留原始来源链接
- 不修改公告内容
- 用户点击跳转到官方网站

### 4.3 用户反馈机制
- 提供"报告错误"功能
- 提供"申请移除"功能
- 联系方式公开

## 六、风险和缓解

### 风险 1：网站改版导致爬虫失效
**缓解**：
- 监控每日爬取数量
- 数量骤降时发送告警
- 保留多个版本的选择器配置

### 风险 2：被网站封禁
**缓解**：
- 严格控制访问频率
- 使用 Cloudflare Workers 的分布式 IP
- 准备备用爬取策略

### 风险 3：数据不准确
**缓解**：
- 数据来源标注
- 用户反馈机制
- 定期人工抽查
